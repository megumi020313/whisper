# 噪声数据预处理说明

## 预处理文件位置

预处理文件保存在：`data/noise_processed.wav`

- **路径**：`code/software/training/data/noise_processed.wav`
- **大小**：约2.6GB（合并了所有274个WAV文件）
- **元数据**：`data/noise_processed.metadata.json`（记录文件列表和修改时间）

## 自动更新机制

### 工作原理

预处理脚本 `merge_data.py` 现在支持**自动检测新数据**和**选择代表性数据**：

1. **首次运行**：自动选择代表性数据并合并
2. **后续运行**：
   - 自动检测 `raw_data/noise/` 目录中的文件变化
   - 如果数据未变化，跳过合并（节省时间）
   - 如果检测到新文件或文件修改，自动重新选择并合并

### 使用方法

```bash
# 自动检测并更新（推荐）- 选择30分钟代表性数据并合并
cd code/software/training
python merge_data.py

# 选择10分钟代表性数据并合并
python merge_data.py --target-duration 600

# 每个类别选择2个文件
python merge_data.py --samples-per-category 2

# 强制重新生成（即使数据未变化）
python merge_data.py --force

# 指定输入输出路径
python merge_data.py --input-dir raw_data/noise --output data/noise_processed.wav
```

### 自动调用机制

**训练脚本会自动调用预处理脚本**：

- ✅ **训练前自动检查**：`train_noise.py` 会在训练前自动检查预处理文件
- ✅ **数据集未更改**：如果数据集未更改，直接使用现有预处理文件，跳过预处理步骤
- ✅ **数据集已更改**：如果检测到数据集变化，自动运行 `merge_data.py` 更新预处理文件
- ✅ **预处理文件不存在**：如果预处理文件不存在，自动运行 `merge_data.py` 生成预处理文件

**无需手动运行**：训练脚本会自动处理所有情况，你只需要运行训练命令即可。

### 手动运行（可选）

如果需要手动运行预处理脚本：

- ✅ **添加新数据后**：运行一次 `python merge_data.py`，脚本会自动检测并重新选择代表性数据
- ✅ **修改现有文件后**：脚本会自动检测文件修改时间，自动重新选择并合并
- ✅ **强制重新生成**：使用 `python merge_data.py --force` 强制重新生成

## 选择代表性数据

### 工作原理

`merge_data.py` 会自动从原始数据集中选择代表性数据：

1. **按类别选择**：从每个噪声类别中随机选择指定数量的文件
2. **控制总时长**：确保选择的文件总时长不超过目标时长（默认30分钟）
3. **合并数据**：将选择的代表性数据合并为单个预处理文件

### 选择策略

- **类别识别**：自动识别数据类别（基于目录结构）
- **随机选择**：从每个类别中随机选择文件（使用随机种子确保可重复）
- **时长控制**：如果总时长超过目标，按文件大小排序，选择文件直到接近目标时长

## 音频时长限制与随机采样

### 问题说明

原始数据集有 **84304秒（约23.4小时）**，但为了减少内存占用，配置中设置了 **3600秒（1小时）** 的限制。

### 改进方案：随机采样

**之前的问题**：简单截断只使用前1小时数据，浪费了剩余22.4小时的数据。

**现在的改进**：使用**随机采样**，每个epoch从全部数据中随机选择1小时的片段：

- ✅ **充分利用全部数据**：每个epoch使用不同的1小时片段
- ✅ **减少内存占用**：仍然只加载1小时数据到内存
- ✅ **提高训练效果**：模型可以学习到更多样化的数据

### 配置选项

在 `config/rnnoise_config.yaml` 中：

```yaml
training:
  max_audio_duration_seconds: 3600        # 限制使用的音频时长（秒）
  use_random_sampling: true               # 是否使用随机采样
```

- `max_audio_duration_seconds: 0`：不限制，使用全部数据（需要足够内存）
- `max_audio_duration_seconds: 3600` + `use_random_sampling: true`：随机采样1小时（推荐）
- `max_audio_duration_seconds: 3600` + `use_random_sampling: false`：只使用前1小时（不推荐）

### 数据使用情况

| 配置 | 实际使用数据 | 说明 |
|------|------------|------|
| `max_duration=0` | 100% (84304秒) | 使用全部数据，需要大量内存 |
| `max_duration=3600` + `random=true` | 随机1小时/epoch | 每个epoch使用不同的1小时片段，充分利用全部数据 |
| `max_duration=3600` + `random=false` | 4.3% (3600秒) | 只使用前1小时，浪费大量数据 |

## 工作流程

### 添加新数据后的流程

1. **添加新WAV文件**到 `raw_data/noise/` 目录
2. **运行预处理脚本**：
   ```bash
   cd code/software/training
   python merge_data.py
   ```
3. **脚本自动检测**：
   - 如果数据未变化 → 跳过合并
   - 如果检测到新文件 → 自动重新合并
4. **开始训练**：
   ```bash
   python train_unified_model.py
   ```

### 训练时的数据使用

1. **加载预处理文件**：`data/noise_processed.wav`（2.6GB）
2. **随机采样**（如果启用）：
   - Epoch 1：使用第 0-3600 秒
   - Epoch 2：使用第 5000-8600 秒（随机）
   - Epoch 3：使用第 20000-23600 秒（随机）
   - ...
3. **特征提取和训练**：在采样的1小时数据上进行

## 性能优化建议

### 如果内存充足

```yaml
training:
  max_audio_duration_seconds: 0           # 不限制，使用全部数据
  use_random_sampling: false             # 不需要随机采样
```

### 如果内存有限（推荐）

```yaml
training:
  max_audio_duration_seconds: 3600       # 限制1小时
  use_random_sampling: true              # 启用随机采样，充分利用数据
```

### 如果内存非常有限

```yaml
training:
  max_audio_duration_seconds: 1800       # 限制30分钟
  use_random_sampling: true              # 仍然使用随机采样
  batch_size: 16                         # 进一步降低batch size
  num_workers: 2                         # 减少worker数量
```

## 常见问题

### Q: 每次训练前都需要运行预处理脚本吗？

**A**: 不需要。只有在添加新数据或修改现有数据后才需要运行。脚本会自动检测数据是否变化。

### Q: 随机采样会影响训练效果吗？

**A**: 不会。随机采样实际上**提高**了训练效果，因为：
- 每个epoch使用不同的数据片段
- 模型可以学习到更多样化的数据
- 避免了只使用前1小时数据的局限性

### Q: 如何知道预处理文件是否是最新的？

**A**: 运行 `python merge_data.py`，如果输出"预处理文件已是最新"，说明数据未变化。

### Q: 可以同时使用多个预处理文件吗？

**A**: 可以。修改配置文件中的 `dataset_path` 指向不同的预处理文件即可。
