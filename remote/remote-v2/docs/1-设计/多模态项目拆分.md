# 📂 项目一：智能听觉感知服务 (Intelligent Auditory Service)
**代号**：`Audio-Sentry`
**定位**：系统的“耳朵” —— 负责听、记、存。

### 1. 项目概述
本项目是一个**只进不出**的数据生产者。它实时接收音频流，并行执行声纹识别（SV）和语音转写（ASR），利用 V3.3 对话智能引擎进行对齐，最终将结构化的“谁在什么时候说了什么”写入 IoTDB 时序数据库。

### 2. 核心功能
*   **VAD 静音过滤**：基于 Silero VAD，只处理人声，过滤噪声。
*   **并行感知**：
    *   **身份识别**：ERes2NetV2 模型提取声纹，1:N 检索确认说话人 ID。
    *   **内容转写**：Faster-Whisper Large-v3 模型生成带时间戳的文本。
*   **对话智能 (V3.3)**：执行词-说话人对齐、边界校正、置信度平滑。
*   **数据持久化**：通过 `IoTDB Session` 将结果写入时序数据库。

### 3. 技术栈与环境
*   **语言**：Python 3.10+
*   **核心库**：`torch`, `torchaudio`, `faster-whisper`, `modelscope`, `iotdb-session`
*   **硬件要求**：NVIDIA V100 (显存占用限制在 **40%** 以内)

### 4. 输入与输出
*   **Input**：16kHz PCM 音频流 / WAV 文件。
*   **Output (IoTDB)**：
    *   **Path**: `root.store_01.audio.{device_id}`
    *   **Fields**: `timestamp` (时间戳), `speaker_id` (文本), `content` (文本), `confidence` (浮点)

### 5. 关键实施步骤 
1.  **完成阶段 2**：编写 `backend/data/iotdb/connector.py`。
2.  **显存限制**：在初始化 Whisper 和声纹模型时，务必监控显存，确保不超过 12GB (V100 32G 的 40%)，为项目二留空间。
3.  **封版**：代码测试通过后，封装为 Docker 镜像或独立 Service 运行。

# 📂 项目二：通用大模型推理服务 (LLM Inference Server)
**代号**：`Brain-Core`
**定位**：系统的“大脑” —— 纯粹的计算单元。

### 1. 项目概述
本项目是一个**无状态**的 API 服务。它不包含任何业务逻辑，只负责将 Qwen2.5 大模型加载到显存中，并以极高的吞吐量响应外部的推理请求。它兼容 OpenAI API 格式，方便任何客户端调用。

### 2. 核心功能
*   **模型托管**：加载 `Qwen2.5-7B-Instruct-GPTQ-Int4` (量化版，速度快显存小)。
*   **并发加速**：使用 `vLLM` 引擎，支持 PagedAttention，极大提高并发吞吐量。
*   **API 服务**：提供 HTTP 接口 (`/v1/chat/completions`)。

### 3. 技术栈与环境
*   **语言**：Python 3.10+
*   **核心库**：`vllm`, `fastapi`, `uvicorn`
*   **硬件要求**：NVIDIA V100 (显存占用限制在 **50%** 左右)

### 4. 接口定义
*   **Endpoint**: `POST http://localhost:8000/v1/chat/completions`
*   **Request Body**:
    ```json
    {
      "model": "Qwen2.5-7B",
      "messages": [{"role": "user", "content": "..."}],
      "temperature": 0.1
    }
    ```

### 5. 关键实施步骤
1.  **部署脚本**：编写启动脚本，核心参数如下：
    ```bash
    python -m vllm.entrypoints.openai.api_server \
      --model /models/llm/Qwen2.5-7B-Int4 \
      --gpu-memory-utilization 0.5 \  # 关键：只吃50%显存
      --port 8000 \
      --trust-remote-code
    ```
2.  **服务化**：配置 Systemd 或 Docker 使其开机自启，常驻后台。

# 📂 项目三：多模态业务编排系统 (Business Orchestrator)
**代号**：`Logic-Flow`
**定位**：系统的“手” —— 协调数据与决策。

### 1. 项目概述
本项目是**轻量级**的业务逻辑中心。它不跑任何重型模型，只负责“搬运”和“指挥”。它从 IoTDB 拉取项目一（听觉）和 P4 服务器（视觉）的数据，拼装成 Prompt，发给项目二（大脑）进行分析，最后处理结果。

### 2. 核心功能
*   **时序对齐**：从 IoTDB 中查询同一时间窗口（如过去 10 秒）内的 `root.store.audio` 和 `root.store.visual` 数据。
*   **Prompt 工程**：将多模态数据填入预设的 Prompt 模板（如：“判断员工是否在推销”）。
*   **推理调用**：通过 HTTP 请求调用项目二的 API。
*   **结果处理**：解析 LLM 返回的 JSON，触发报警或存回 IoTDB 的 `root.store.analysis`。

### 3. 技术栈与环境
*   **语言**：Python 3.10+ (或 Go/Java，看你喜好，推荐 Python)
*   **核心库**：`iotdb-session`, `requests`, `pydantic`
*   **硬件要求**：任意 CPU (极低资源消耗)

### 4. 逻辑流程 (伪代码)
```python
while True:
    # 1. 从 IoTDB 获取最近 10秒 数据
    audio_data = iotdb.query("root.store.audio", last_10s)
    visual_data = iotdb.query("root.store.visual", last_10s)
    
    if audio_data:
        # 2. 组装 Prompt
        prompt = f"语音内容：{audio_data.text}，视觉物体：{visual_data.objects}，请分析服务意图。"
        
        # 3. 调用项目二
        response = requests.post("http://localhost:8000/...", json={...})
        
        # 4. 处理结果
        save_result(response.json())
    
    time.sleep(1)
```

### 5. 关键实施步骤
1.  **开发**：这是你接下来写代码的主要阵地。
2.  **调试**：因为不依赖显卡，你可以在本地电脑写代码，远程连服务器的 IoTDB 和 LLM 接口进行调试。
