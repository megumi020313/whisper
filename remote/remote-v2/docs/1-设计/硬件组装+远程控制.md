好的，这份指南将作为您的**“硬件白痴”说明书**，手把手带您完成从零件到可运行的音频采集终端的全过程。

我们将整个过程分为 **三大步骤**：**硬件组装**、**系统烧录与配置**、**软件部署与运行**。

### 🛠️ 第一步：硬件组装 (Hardware Assembly)

**目标**：像搭乐高一样，把所有零件安全地组装在一起。

**所需工具**：一把小号十字螺丝刀。

1.  **焊接排针 (Pin Soldering)**
    *   **检查**：您的树莓派 Zero 2 W 主板上是否已经焊好了一排彩色的针脚（GPIO排针）？
    *   **如果已焊好**：直接跳到下一步。
    *   **如果没焊好**：这是唯一需要动用电烙铁的步骤。如果您完全没经验，**强烈建议找个修手机或电脑的店，花10-20元让师傅帮您焊好**。告诉他：“师傅，麻烦帮我把这个40Pin的排针焊到这个板子上，对齐就行。”

2.  **安装麦克风扩展板 (ReSpeaker HAT)**
    *   **操作**：将 ReSpeaker 2-Mics Pi HAT（那块带两个小银色麦克风的板子）对准树莓派上的排针，**轻轻地、垂直地**按下去，直到它完全插紧。
    *   **检查**：确保扩展板和树莓派主板之间没有缝隙，所有针脚都插到位了。

3.  **安装UPS扩展板 (UPS HAT)**
    *   **操作**：UPS扩展板通常通过底部的4个铜柱和螺丝固定在树莓派的背面。
    *   先将铜柱拧到树莓派的4个安装孔上。
    *   然后将UPS板对准铜柱，用螺丝固定。
    *   UPS板会通过几个弹簧探针（Pogo Pin）接触到树莓派背面的电源触点，**确保这些探针能稳固地顶在树莓派上**。

4.  **连接电池 (Battery Connection)**
    *   **操作**：找到UPS板上的电池接口（通常是一个白色的小插座），将1000mAh锂电池的插头插进去。**注意正负极，插头有防呆设计，不要用蛮力**。

5.  **插入SD卡 (SD Card Insertion)**
    *   **操作**：将您准备好的MicroSD卡（TF卡）插入树莓派主板侧面的卡槽中，轻轻按到底，会有一个“咔哒”声。

6.  **连接5G网卡 (5G WiFi Dongle)**
    *   **操作**：树莓派 Zero 2 W 只有一个 MicroUSB OTG 接口。您需要一个 **MicroUSB OTG 转接头**（通常买网卡会送）。
    *   将转接头插入树莓派的 **USB** 接口（不是 PWR IN 那个），然后将5G USB网卡插入转接头的另一端。

7.  **装入外壳 (Enclosure Assembly)**
    *   **操作**：将组装好的整个“三明治”结构小心地放入3D打印外壳中，并用螺丝固定。
    *   **检查**：确保外壳为麦克风、USB接口、SD卡槽和充电口都留出了合适的开口。

**至此，硬件组装完成！** 您的成品应该是一个紧凑的小盒子。

### 🖥️ 第二步：系统烧录与配置 (System Flashing & Configuration)

**目标**：为树莓派安装操作系统，并配置好网络和驱动。

**所需工具**：一台电脑，一个读卡器。

1.  **烧录操作系统 (Flashing OS)**
    *   **下载工具**：在电脑上下载并安装 **Raspberry Pi Imager** 官方工具。
    *   **选择系统**：打开 Imager，选择 “Raspberry Pi OS (Legacy, 64-bit) Lite”。**Lite版没有桌面，最省电**。
    *   **高级设置**：在 Imager 中点击右下角的齿轮图标，进行**预配置**：
        *   **设置主机名**: `audio-terminal-01`
        *   **启用 SSH**: 勾选
        *   **设置用户名和密码**: 例如 `pi` / `your_password`
        *   **配置 WiFi**: **暂时先配置您家里的2.4G WiFi**，用于首次启动和调试。我们稍后再配置5G网卡。
    *   **烧录**：将SD卡通过读卡器插入电脑，在 Imager 中选择它，然后点击“写入”。

2.  **首次启动与SSH登录 (First Boot & SSH Login)**
    *   **操作**：将烧录好的SD卡插回树莓派。通过 MicroUSB 数据线连接到 **PWR IN** 接口给它供电。等待约1-2分钟。
    *   **登录**：在电脑上打开终端（Windows用PowerShell或CMD），输入 `ssh pi@audio-terminal-01.local`。输入您刚才设置的密码，成功登录后，您就进入了树莓派的命令行界面。

3.  **配置麦克风驱动 (ReSpeaker Driver)**
    *   **操作**：在SSH终端中，依次执行以下命令来安装 ReSpeaker 驱动：
        ```bash
        sudo apt-get update
        sudo apt-get install git
        git clone https://github.com/respeaker/seeed-voicecard.git
        cd seeed-voicecard
        sudo ./install.sh
        sudo reboot
        ```
    *   **验证**：重启后，重新SSH登录，执行 `arecord -l`。如果您看到类似 `seeed-2mic-voicecard` 的设备，说明麦克风驱动安装成功。

4.  **配置5G网卡驱动 (5G WiFi Driver)**
    *   **这是最关键也最容易出问题的一步**，因为RTL8811/8821芯片通常需要编译驱动。
    *   **操作**：在SSH终端中，执行以下命令：
        ```bash
        sudo apt-get install raspberrypi-kernel-headers dkms
        git clone https://github.com/morrownr/8821au-20210708.git
        cd 8821au-20210708
        sudo ./install-driver.sh
        sudo reboot
        ```
    *   **验证**：重启后，执行 `iwconfig`。如果您看到 `wlan0` 和 `wlan1` 两个设备，说明5G网卡驱动安装成功。`wlan1` 就是您的5G网卡。

5.  **连接到5G网络 (Connect to 5G Network)**
    *   **操作**：编辑网络配置文件 `sudo nano /etc/wpa_supplicant/wpa_supplicant.conf`。
    *   在文件末尾添加您的5G WiFi信息：
        ```
        network={
            ssid="Your_5G_WiFi_Name"
            psk="Your_5G_WiFi_Password"
        }
        ```
    *   保存并退出，然后重启 `sudo reboot`。

### 🏃 第三步：软件部署与运行 (Software Deployment & Running)

**目标**：在树莓派上运行音频采集和上传程序。

1.  **安装基础软件 (Install Basic Software)**
    *   **操作**：在SSH终端中，安装 `ffmpeg` 和 `git`：
        ```bash
        sudo apt-get update
        sudo apt-get install ffmpeg git
        ```

2.  **编写音频采集脚本 (Audio Capture Script)**
    *   **操作**：在树莓派上创建一个 Python 脚本，例如 `audio_uploader.py`。这个脚本的核心功能是：
        1.  在后台启动 `ffmpeg` 进程，让它持续录音并自动切片（例如每10秒一个 `.opus` 文件）。
        2.  监控存放切片的文件夹。
        3.  一旦有新文件生成，就通过 gRPC 将其发送到您的边缘服务器（E5+P4+V100）的IP地址。

    *   **FFmpeg 录音命令示例** (在Python中用 `subprocess.Popen` 运行):
        ```bash
        # hw:1,0 是 ReSpeaker 麦克风的设备号，您可能需要根据 arecord -l 的结果调整
        ffmpeg -f alsa -i hw:1,0 -ac 1 -ar 16000 -c:a libopus -b:a 24k -f segment -segment_time 10 -strftime 1 /home/pi/audio_clips/%Y%m%d_%H%M%S.opus
        ```

3.  **编写 gRPC 上传逻辑 (gRPC Upload Logic)**
    *   **操作**：在 `audio_uploader.py` 中，使用 `grpc` 库，实现一个客户端，连接到您服务器上运行的 gRPC 服务。
    *   您需要先在服务器端定义好 `.proto` 文件，并生成 Python 代码，然后将生成的客户端代码 (`_pb2.py` 和 `_pb2_grpc.py`) 复制到树莓派上。

4.  **设置开机自启 (Auto-start on Boot)**
    *   **操作**：为了让设备通电后自动开始工作，您需要将 `audio_uploader.py` 脚本设置为一个 `systemd` 服务。
    *   创建一个服务文件 `sudo nano /etc/systemd/system/audio-uploader.service`，内容类似：
        ```ini
        [Unit]
        Description=Audio Uploader Service
        
        [Service]
        ExecStart=/usr/bin/python3 /home/pi/audio_uploader.py
        Restart=always
        User=pi
        
        [Install]
        WantedBy=multi-user.target
        ```
    *   然后启用并启动服务：
        ```bash
        sudo systemctl enable audio-uploader.service
        sudo systemctl start audio-uploader.service
        ```

**至此，您的音频采集终端就完全配置好了！** 只要给它通上电，它就会自动连接到5G WiFi，开始录音，并将音频切片源源不断地发送到您的边缘服务器进行后续的多模态分析。



**远程控制**:

当然可以，这是一个至关重要的功能。让录音的启停处于可控状态，不仅是业务需求，也是合规和保护隐私的基本要求。

**总的来说，控制逻辑的“开关”应该放在您树莓派上的主程序 `audio_uploader.py` 中。**

您可以把它想象成一个“状态机”，程序内部有一个变量，例如 `is_recording = False`。当这个变量为 `True` 时，`ffmpeg` 进程就启动并录音；当它为 `False` 时，`ffmpeg` 进程就被终止。

下面我为您提供两种最实用、最可靠的控制方案，**强烈建议您将两种方案都实现**，以应对不同场景。

---

### 方案一：物理开关（最可靠、最直观）

**适用场景**：员工佩戴设备，需要手动开始/结束一天的工作录音。这是最基础、最可靠的控制方式，不受网络影响。

#### 1. 所需硬件
*   **一个自锁按钮 (Self-locking Button)**：按一下锁定（开），再按一下弹起（关）。
*   **一个LED灯**：用于状态指示（例如：亮灯=录音中，灭灯=待机）。
*   **几根杜邦线 (Dupont Wires)**：用于连接。

#### 2. 接线示意图
您需要将按钮和LED灯连接到树莓派的GPIO引脚上。

```
   树莓派GPIO引脚
   -----------------
   (Pin 1) 3.3V Power  ------> [ 按钮的一端 ]
   (Pin 11) GPIO 17   <------ [ 按钮的另一端 ]

   (Pin 13) GPIO 27   ------> [ LED灯的长脚(+) ]
   (Pin 9) Ground     <------ [ LED灯的短脚(-) ]
   -----------------
```

#### 3. 软件实现逻辑 (`audio_uploader.py`)
我们需要使用 `RPi.GPIO` 库来监听按钮的按下事件，并控制LED灯。

```python
import RPi.GPIO as GPIO
import subprocess
import time
import threading

# --- 全局状态变量 ---
# 使用线程安全的 Event 来控制状态
recording_event = threading.Event() 
ffmpeg_process = None

# --- GPIO 设置 ---
BUTTON_PIN = 17
LED_PIN = 27

def setup_gpio():
    GPIO.setmode(GPIO.BCM)
    # 设置按钮引脚为输入，并启用内部上拉电阻
    # 这意味着默认是高电平，按钮按下接地后变为低电平
    GPIO.setup(BUTTON_PIN, GPIO.IN, pull_up_down=GPIO.PUD_UP)
    GPIO.setup(LED_PIN, GPIO.OUT)
    # 添加中断事件，当检测到下降沿（按钮按下）时，调用 toggle_recording 函数
    GPIO.add_event_detect(BUTTON_PIN, GPIO.FALLING, callback=toggle_recording, bouncetime=300)

def toggle_recording(channel):
    """中断回调函数：当按钮被按下时，翻转录音状态"""
    if recording_event.is_set():
        print("按钮按下：停止录音...")
        recording_event.clear() # 设置为 False
    else:
        print("按钮按下：开始录音...")
        recording_event.set() # 设置为 True

def manage_recording_process():
    """主循环：根据 recording_event 的状态来管理 ffmpeg 进程"""
    global ffmpeg_process
    while True:
        if recording_event.is_set(): # 如果应该录音
            GPIO.output(LED_PIN, GPIO.HIGH) # 点亮LED
            if ffmpeg_process is None or ffmpeg_process.poll() is not None:
                print("启动 ffmpeg 进程...")
                # 启动 ffmpeg 子进程
                ffmpeg_command = "ffmpeg -f alsa -i hw:1,0 ..." # 您的ffmpeg命令
                ffmpeg_process = subprocess.Popen(ffmpeg_command, shell=True)
        else: # 如果不应该录音
            GPIO.output(LED_PIN, GPIO.LOW) # 熄灭LED
            if ffmpeg_process is not None and ffmpeg_process.poll() is None:
                print("终止 ffmpeg 进程...")
                ffmpeg_process.terminate() # 终止子进程
                ffmpeg_process = None
        
        time.sleep(1) # 每秒检查一次状态

# --- 主程序 ---
if __name__ == "__main__":
    setup_gpio()
    
    # 在一个独立的线程中运行录音管理逻辑
    recording_thread = threading.Thread(target=manage_recording_process)
    recording_thread.daemon = True
    recording_thread.start()
    
    print("录音控制系统已启动。按下按钮来开始/停止录音。")
    
    # 主线程可以做其他事，比如 gRPC 上传
    try:
        while True:
            # 这里可以写您的 gRPC 上传逻辑
            # 监控文件夹，上传文件等
            time.sleep(5)
    except KeyboardInterrupt:
        GPIO.cleanup()
```

### 方案二：远程指令控制（最专业、最灵活）

**适用场景**：店长或管理员通过中央控制台（例如一个网页），远程命令所有员工的设备开始或停止录音。

#### 1. 所需硬件
*   无新增硬件。

#### 2. 实现原理
您已经在使用 gRPC 将音频数据从树莓派**单向**发送到服务器。我们可以将这个连接升级为**双向流 (Bi-directional Stream)**。
*   **上行流**：树莓派继续发送音频切片。
*   **下行流**：服务器可以随时通过这个已建立的连接，向树莓派发送指令（如 `{"command": "START"}` 或 `{"command": "STOP"}`）。

#### 3. 软件实现逻辑

1.  **修改 `.proto` 文件**
    您需要定义一个可以双向通信的 gRPC 服务。
    ```protobuf
    syntax = "proto3";

    service AudioStreamer {
      // 双向流 RPC
      rpc StreamAudio(stream ClientMessage) returns (stream ServerCommand);
    }

    // 客户端发给服务器的消息
    message ClientMessage {
      bytes audio_chunk = 1;
      string device_id = 2;
    }

    // 服务器发给客户端的指令
    message ServerCommand {
      string command = 1; // "START", "STOP", "REBOOT"
    }
    ```

2.  **修改树莓派 `audio_uploader.py`**
    您的 gRPC 客户端需要在一个**独立的线程**中运行，以同时处理“发送音频”和“接收指令”。

    ```python
    # ... (接方案一的代码) ...

    def grpc_communication_thread(server_address):
        """gRPC 双向通信线程"""
        
        def generate_audio_messages():
            """生成器：从文件队列读取音频并打包成消息"""
            while True:
                # 从文件队列获取一个音频切片
                audio_data = get_audio_file_from_queue()
                if audio_data:
                    yield ClientMessage(audio_chunk=audio_data, device_id="terminal-01")
                else:
                    time.sleep(1)

        with grpc.insecure_channel(server_address) as channel:
            stub = AudioStreamerStub(channel)
            
            # response_iterator 是一个服务器指令的流
            response_iterator = stub.StreamAudio(generate_audio_messages())
            
            print("gRPC 连接已建立，开始监听远程指令...")
            try:
                for command in response_iterator:
                    print(f"收到远程指令: {command.command}")
                    if command.command == "START":
                        recording_event.set() # 设置为 True
                    elif command.command == "STOP":
                        recording_event.clear() # 设置为 False
            except grpc._channel._Rendezvous as e:
                print(f"gRPC 连接断开: {e}")

    # --- 主程序 ---
    if __name__ == "__main__":
        setup_gpio()
        
        # 启动录音管理线程
        recording_thread = threading.Thread(target=manage_recording_process)
        recording_thread.daemon = True
        recording_thread.start()
        
        # 启动 gRPC 通信线程
        grpc_thread = threading.Thread(target=grpc_communication_thread, args=("your_server_ip:50051",))
        grpc_thread.daemon = True
        grpc_thread.start()
        
        print("系统已启动。可通过物理按钮或远程指令控制录音。")
        
        # 阻塞主线程
        try:
            while True:
                time.sleep(10)
        except KeyboardInterrupt:
            GPIO.cleanup()
    ```
