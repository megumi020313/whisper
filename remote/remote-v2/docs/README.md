## 📂 文档分类说明

### 1-设计/
架构设计、模块设计、系统设计文档

### 200-需求管理/
- 需求文档命名：`REQ-YYYYMMDD-序号-需求名称.md`
- 包含需求概述、原子性拆分、任务定义、验收标准

### 201-Bug修复任务管理/
- Bug文档命名：`BUG-YYYYMMDD-序号-问题描述.md`
- 包含Bug信息、问题分析、修复方案、测试验证

### 202-优化任务管理/
- 优化文档命名：`OPT-YYYYMMDD-序号-优化描述.md`
- 包含优化目标、现状分析、优化方案、优化效果

### 203-说明文档/
项目说明、配置说明、结构说明等综合性文档

### design/
- `index/` - 函数索引总览
- `modules/` - 各模块函数索引

### changelog/
- 变更日志命名：`CHANGLOG-YYYYMMDD-HHMMSS.md`
- 记录每次代码变更的详细信息

### logs/
- 项目开发工作日志（按时间顺序记录）

## 📌 文档维护规范

### 创建新文档时

1. **选择正确的目录**
   - 设计文档 → `1-设计/`
   - 需求文档 → `200-需求管理/`
   - Bug文档 → `201-Bug修复任务管理/`
   - 优化文档 → `202-优化任务管理/`
   - 说明文档 → `203-说明文档/`

2. **使用正确的命名格式**
   - 需求：`REQ-YYYYMMDD-序号-需求名称.md`
   - Bug：`BUG-YYYYMMDD-序号-问题描述.md`
   - 优化：`OPT-YYYYMMDD-序号-优化描述.md`
   - 变更日志：`CHANGLOG-YYYYMMDD-HHMMSS.md`

3. **更新索引文件**
   - 更新对应目录的 `README.md`
   - 更新本文档索引（如有必要）

### 修改文档时

1. **保持一致性**
   - 遵循现有文档的格式
   - 使用统一的术语

2. **记录变更**
   - 在变更日志中记录修改
   - 在开发日志中记录重要变更

3. **更新引用**
   - 如果文件路径改变，更新所有引用
